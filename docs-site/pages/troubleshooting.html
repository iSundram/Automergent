Automergent Troubleshooting & FAQ

Diagnose common issues, understand error codes, check terminal compatibility, and find answers to frequently asked questions.

Quick Diagnosis: Run automergent doctor or /doctor inside the TUI to automatically test your environment, API keys, provider latency, LSP diagnostics, and disk permissions.

Provider & Connection Issues

⚠️

Provider Connection Failed

connection

Automergent cannot reach the AI provider API endpoint.

Symptom Error: Provider connection failed — could not reach api.example.com
Solutions
  • Verify your API key is configured: run amt /env or check GOOGLE_API_KEY / GEMINI_API_KEY.
  • Check network connectivity: curl -s -o /dev/null -w "%{http_code}" https://generativelanguage.googleapis.com
  • If using a custom base URL, confirm it includes the full path (e.g., https://api.openai.com/v1).
  • For corporate proxies, set HTTP_PROXY / HTTPS_PROXY environment variables.
  • Check provider status pages for outages (Google AI Studio, Vertex AI, OpenAI).
📅

Context Window Too Long

context

The conversation context has exceeded the model's context window limit.

Symptom Error: CONTEXT_TOO_LONG — context window exceeded (198,000 / 128,000 tokens)
Solutions
  • Run /compact to summarize and compress the conversation history.
  • Monitor usage in real-time with /context — compact when approaching 80%.
  • Start a fresh session: /new — carry over key context manually.
  • Automergent supports up to 1M+ tokens on Gemini 3.6 / Vertex AI models natively.
Tip: Automergent automatically triggers compaction when reaching autoCompressAt: 0.55 (55% budget).
🔒

Tool Confirmation Keeps Appearing

permissions

The approval prompt appears repeatedly for safe, routine operations.

Solutions
  • Switch approval mode: /mode accept-edits or /mode auto (caution).
  • Configure permissions in ~/.automergent/config.yaml or .automergent/config.yaml.
  • Cycle approval modes anytime with Shift+Tab in the terminal.
📱

TUI Looks Broken

display

Characters are garbled, colors missing, or layout is misaligned.

Solutions
  • Ensure your terminal supports truecolor (24-bit color). Run /env to check.
  • Try a modern terminal: iTerm2, WezTerm, Alacritty, kitty, Ghostty, Windows Terminal.
  • Set TERM=xterm-256color as a fallback.
  • Increase terminal window to at least 80×24 characters (recommended 120×40).
🔧

Build Fails

build

The Go build fails with compilation or linking errors.

Symptom go build ./cmd/automergent: build constraints exclude all Go files or CGO-related errors.
Solutions
  • Ensure Go 1.25+ is installed: go version
  • CGO is required for tree-sitter AST parsing: CGO_ENABLED=1 go build ./cmd/automergent
  • On Linux, install gcc or musl-gcc for CGO compilation.
  • On macOS, install Xcode Command Line Tools: xcode-select --install
💾

Session Not Saving

storage

Session data is lost between runs or history is not persisted.

Solutions
  • Check session directory exists and is writable: ls -la ~/.automergent/sessions/
  • Ensure disk space is available: df -h ~/.automergent/
  • Run automergent doctor to validate storage permissions.
🤖

Sub-Agent Not Responding

agent

A spawned sub-agent appears stuck or never completes.

Solutions
  • Check agent status: /agents — review active and completed agents in the fleet.
  • Cancel a stuck agent: /cancel agent <id>
  • Use /agents kill-all to terminate all stuck background subagents.
🎨

Theme Colors Look Wrong

theme

Colors are washed out, incorrect, or appear as solid blocks.

Solutions
  • Verify truecolor support: /env — check Truecolor field.
  • Switch themes: /theme modern, /theme catppuccin, /theme tokyonight, /theme dracula, etc.
  • For tmux/screen, use set -ga terminal-overrides ",*256col*:Tc" in .tmux.conf.
🔌

MCP Server Not Connecting

mcp

Custom MCP servers fail to start or tools are not available.

Solutions
  • Check MCP config in ~/.automergent/config.yaml under mcp.servers for syntax errors.
  • Verify transport type matches: "stdio" (default) or "sse".
  • For stdio servers, ensure the binary is in PATH or uses an absolute path.
  • Run /mcp in the TUI to check server connectivity and registered dynamic tools.
🛡️

Sandbox Blocking Legitimate Operations

sandbox

File writes or commands are blocked by the security sandbox.

Solutions
  • Check sandbox config in .automergent/config.yaml.
  • Add allowed paths: allowedWritePaths: [".", "/tmp/build"]
  • Run with --no-sandbox or configure sandbox: auto in config.
  • Use /doctor to see sandbox status and recent violations.
  • For debugging, run with --no-sandbox flag (not recommended in production).

Performance Tips

⚡ Model Selection

  • Use a fast model (GPT-4o-mini, Haiku) for read-only sub-agents like /explore.
  • Reserve heavyweight models (Opus, GPT-4o) for complex reasoning and code generation.
  • Use /model to switch mid-session based on task complexity.

📊 Context Management

  • Run /context periodically to monitor window usage.
  • Compact at 80% capacity — don't wait for errors.
  • Start new sessions for unrelated tasks rather than carrying stale context.

🤖 Sub-Agents

  • Use sub-agents for parallel work — research + implement simultaneously.
  • Keep sub-agent tasks focused and well-scoped for faster completion.
  • Set appropriate thinking budget — lower for simple tasks, higher for complex refactors.

🚀 Session Optimization

  • Compact regularly during long sessions (every 20–30 min).
  • Use /summary to generate session summaries before starting new work.
  • Close idle sub-agents to free up context and API budget.

Security FAQ

🛡️ How Sandboxing Works

Automergent runs a sandboxed environment that restricts file writes and command execution to approved paths and commands. The sandbox operates at the tool-execution level — each write or shell operation is checked against a configurable allowlist.

  • File writes: Restricted to the current working directory and explicitly allowed paths.
  • Command execution: Only commands matching an allowlist pattern can run.
  • Network: Outbound network is unrestricted by default but can be limited via .opencode/sandbox.json.

🚫 What Gets Blocked by Default

  • Writes to system directories (/etc, /usr, /var)
  • Execution of destructive commands (rm -rf /, dd, mkfs)
  • Modifications to files outside the project directory
  • Sensitive file access (~/.ssh, ~/.aws/credentials)
  • Installation of system packages without explicit approval

📁 Configuring Write Paths

Add custom paths to the sandbox allowlist:

{
  "write": [
    "./src/**",
    "./tests/**",
    "./config/**",
    "/usr/local/lib/myproject/**"
  ],
  "commands": [
    "npm run *",
    "cargo test",
    "go test ./...",
    "pytest"
  ]
}

Place this in .opencode/sandbox.json at your project root.

🔐 Secrets Scanning Coverage

  • Automergent scans file diffs for patterns matching common secret formats (API keys, tokens, passwords).
  • Coverage includes: AWS keys, GitHub tokens, npm tokens, generic API keys, private keys.
  • Detected secrets are redacted from output and the user is warned.
  • Custom patterns can be added to .automergent/config.yaml.

🛠️ Dependency Audit Support

  • Automergent can run npm audit, cargo audit, govulncheck, or pip-audit via sub-agents.
  • Vulnerability reports are summarized with severity levels and remediation suggestions.
  • Configure automated audits in your CI workflow using /workflow.

Terminal Compatibility

🔵 Truecolor Support

Automergent uses truecolor (24-bit) for themes and diff rendering. Check support:

# Run in your terminal
echo -e "\e[38;2;255;100;0mTruecolor\e[0m"

# Or check via Automergent
/env   # look for "Truecolor: yes"
TerminalTruecolorNotes
iTerm2YesFull support
WezTermYesFull support
AlacrittyYesFull support
kitty / GhosttyYesFull support
Windows TerminalYesRequires Windows 10+
tmuxPartialRequires set -g default-terminal "xterm-256color"
screenNoFalls back to 256-color
cmd.exeNoUse Windows Terminal instead

✨ Unicode Rendering

  • Minimum: UTF-8 encoding with box-drawing characters.
  • Recommended: Full Unicode support including glyphs.
  • If characters render as ?? or boxes, set noAnimation: true or noColor: true in config.

📐 Minimum Terminal Size

Automergent requires a minimum of 80 columns × 24 rows. Recommended: 120×40 for optimal diff and code viewing. Use /env to check your current terminal dimensions.
